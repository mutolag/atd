# Обоснование ELT (модуль Г)

## Выбор: ELT, не классический ETL

1. **Extract + Load** — детекции попадают в Silver «как есть» (`kafka_to_silver`), без тяжёлых трансформаций на входе.
2. **Transform** — агрегации 30 мин, перцентили, доли типов ТС выполняются при загрузке в ClickHouse Gold (`silver_to_gold_batch.py`).

## Почему так для конкурса

- Потоковая очистка и отсев аномалий уже в модуле В — не дублируем в batch.
- Silver остаётся **единым источником правды** для пересчёта витрин без повторного YOLO.
- ClickHouse эффективен для `GROUP BY window_start, camera_id, direction` — transform ближе к хранилищу аналитики (типичный ELT в Medallion).

## Trade-off

| ETL | ELT (наше) |
|-----|------------|
| Трансформация до PG | PG хранит события, проще аудит |
| Дублирование логики stream/batch | Batch только агрегаты |
| Сложнее late replay | Watermark + пересчёт из Silver |

## LTE

Пакетный пересчёт **после** накопления Silver (Late Transform on schedule) — согласуется с Airflow каждые 30 мин и критерием учёта опоздавших данных.
